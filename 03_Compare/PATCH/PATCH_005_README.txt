要望内容:
  03 Compare は「同じ建物で工法だけが違うとき、環境負荷と事業性が
  どれだけ変わるか」を示すもの。単価や事業前提が違うままでは比較に
  ならないため、各Projectが出した単価を一覧化し、人が採用単価を選び、
  その単価で比較できるようにする。コピーは Compare が作るフォルダーの
  中に置く。

対応:
  新タブ「7. 比較前提表」を追加した。手順は次のとおり。
    1. 「一覧を作成」— 選択済みの元Projectを読み、4つの一覧を作る。
    2. 人が決める。
    3. 「比較用コピーを作成」— 新しいフォルダーへ前提表とコピーを書く。

  A 除外工種リスト（編集可）
      工法固有の工種（構造材・RC外装など）は単価差・範囲差の両方から除外。
      同じキーでも仕事が違う工種（型枠・コンクリート・鉄筋・断熱材）は
      単価差から除外し、範囲差には残す。画面で区分を変更でき、
      実際に使った区分表は前提表JSONに保存される。
  B 単価差リスト
      共通工種と設備一式の単価を全Project分並べ、差の有無・倍率・
      各候補の出典と範囲（材工共か材料のみか）を表示。
      行をダブルクリックして「どのProjectの単価を採用するか」
      「個別のまま」「手入力」を選ぶ。
  C 範囲差リスト
      片方にしか無い工種、どのProjectにも1つも無い部位（外装仕上げなど）、
      単位が食い違う工種を列挙。決定は「工法差として了承」か
      「元Projectの数量を見直す」。数量の修正は元Projectで行う。
  D 事業前提
      Module 5/6/7 の設定のうち値が違うものと、必ず統一すべき家賃を表示。
      家賃は「市場家賃を直接入力」のみ認め、建設費からの利回り逆算は
      比較不可として拒否する。
  E 工法差の前提（表示のみ）
      構造部位・建替／全面更新の年・骨組み継続の年。統一せず並べて示す。

  出力（すべて新しいフォルダーの中）:
    <親>\YYMMDD_HHMM_比較_<名前>\
        YYMMDD_HHMM_AZRAS_COMPARISON_PREMISE_BOOK.json
        <元名>__CMP\<元名>__CMP.json   （Project数ぶん）
  前提表には、元Projectのパス・内容のSHA256・保存時刻、使用した区分表、
  一覧と決定内容、版（決定内容のハッシュ）を記録する。
  コピーには新しい project_id、comparison_copy マーカー、統一単価
  （pricing_status = comparison_group_confirmed）、統一した設備一式、
  統一した事業前提を書き込み、Module 5/6/7 を「再計算待ち」にする。
  単価データの紐付けID（PATCH_038 project_binding）もコピーのIDへ
  書き換える（書き換えないとエンジンが単価を破棄する）。
  元Project は読むだけで、一切変更しない。

  読込時の検証（「保存データの整合性確認」に統合）:
    ・元Projectが見つからない／作成後に更新されている
    ・コピーが再計算されていない
    ・別の版の前提表で値付けされている
    ・コピー間で前提表の版や家賃前提が揃っていない
    ・コピーと元Projectが混在している
