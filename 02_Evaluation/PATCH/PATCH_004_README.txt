PATCH_004 — 260919 UTC — v2.2.0
========================================

対象ファイル:
  - core/ui_style.py（create_scrollable_pane_split を新規追加）
  - module4/app.py（画面分割位置の変更、CO₂グラフの移動）
  - module6/app.py（画面分割位置の変更）

要望内容:
  マルコ氏より、実際にModule4・Module6を動かしたスクリーンショットを
  提示のうえ、以下の指摘・要望があった。
    環境（Module4）:
      1. 「長期環境評価を実行」の文字の上で画面を2分割にする。
      2. グラフは「LCAモジュール区分クロスウォーク」の右横に移動する。
    投資評価（Module6）:
      1. 「投資評価を計算」の文字の上で画面を2分割にする。
    共通の問題意識：
      投資評価（および環境）の結果は、実際には添付画面のさらに下に
      続いているが、一見しただけではそれに気づかない。

原因:
  従来の構成（PATCH_194/195/196）は、モジュール画面全体を
  create_scrollable_module_page()による1つの外側スクロール
  キャンバスで包み、その中に「upper（条件入力＋実行ボタン）」と
  「lower_host（固定高さ450pxの内側スクロール領域、結果テーブル・
  グラフ・クロスウォーク等）」を単純に縦積みしていた。この場合：
    - upperとlower_hostは外側スクロールに連動して一緒に動くため、
      「上段は固定、下段だけがスクロールする」という明確な画面分割には
      なっていなかった。
    - lower_host自体も固定450px程度の内側スクロール領域を持つため、
      外側スクロールで一度下までスクロールしても、その中にさらに
      スクロールが必要な内容（クロスウォーク表やグラフ）が残っており、
      二重スクロール構造が「もう続きはない」という誤解を招いていた。
  なお、PATCH_194で一度ttk.Panedwindowによるドラッグ可能な分割を
  試みたが、「外側スクロールページのレイアウト処理により、
  Panedwindowのサッシュが下端にリセットされ、結果側ペインの高さが
  ほぼ0になる」という不具合（PATCH_195/196）が過去に発生したため、
  それ以降は分割を諦めて固定高さの縦積みに変更されていた経緯がある。

対応:
  core/ui_style.pyに新しい共通関数create_scrollable_pane_split()を
  追加した。これはPanedwindowを「外側スクロールキャンバスの中」では
  なく「モジュールウィンドウ（Toplevel）に直接」配置する点が
  PATCH_194時点との違いであり、過去の不具合の原因だった
  「外側スクロールのレイアウト処理とPanedwindowのサッシュ位置調整の
  競合」が構造的に起こらない。上下2ペインはそれぞれ独立した
  Canvas＋スクロールバーを持ち、マウスホイールはポインタが実際に
  乗っているペイン側のCanvasへ振り分けられる（両方が同時にスクロール
  してしまうことはない）。

  Module 4・Module 6ともに、画面構成を
    上段（ドラッグ可能なサッシュ）
    下段
  の2分割に変更し、分割位置を「長期環境評価を実行」「投資評価を計算」
  の各実行ボタンのすぐ上（＝ボタンより上は上段、ボタン自体と結果は
  下段）とした。初期表示は上段:下段=約34:66とし、下段（結果表示側）に
  画面の大半を割り当てている。

  Module 4ではさらに、CO₂累積グラフを「長期環境評価結果／年別環境負荷
  タイムライン」の3列目から外し、「LCAモジュール区分クロスウォーク」
  テーブルの右横（Panedwindowの2ペイン横並び）に配置し直した。
  Module 6の投資回収グラフ（①単純投資回収／②現在価値ベース回収）は
  位置の変更依頼がなかったため、既存の配置（キャッシュフロー表の下）
  のまま。

  なお、page（外側スクロールキャンバス）に直接ぶら下がっていた
  Module 6の5つの注意書きラベル（保険料の扱い・維持管理費の重複防止・
  4つの率は別条件・税金の取扱い・工法比較時の注意）は、pageという
  親が無くなったため、コード上の記述位置（実行ボタン直前）に合わせて
  upper（上段・条件入力側）の子に変更した。
